# GranPal VNext 试点设计（主题化 IA · 标签页 · 提醒 · AI 通道可行性）

版本：1.0（2026-10-28）· 对应实现：v0.1.3 · 过程记录：[PILOT-VNEXT-LOG.md](PILOT-VNEXT-LOG.md)

适用范围：**只改 `cml-workbench` 这一个仓**。本文既是本轮改造的设计依据，也是"能否作为整仓迭代范式"的评估报告。
结论先说：

1. **可以作为一个"方法范式"复用**（主题 3 步旅程 + 每屏 ≤2 类信息 + 文案预算 + 诚实的 AI 能力闸门），
   但**不能照抄页面结构**——主题来自本病种的患者旅程，换癌种必须重做主题与旅程（§6）。
2. **后台静默 LLM 通道在本仓/当前宿主契约下不可行**（证据 §5）。本轮实现的是"本机规则提醒 + 用户主动把提示词交给宿主原生会话"，
   并明确标注「本机未接入模型」；**没有伪造任何 AI 分析结果**。

## 1. 现状问题清单（可核验，均可指到具体界面 / 代码）

### 1.1 折线图字体太大：根因是 viewBox 被拉伸，不是字号本身

| 位置 | 事实 | 后果 |
| --- | --- | --- |
| `public/style.css`（`svg.chart`） | `width:100%` + `viewBox="0 0 640 …"`（`chartSVG` 的 `W = 640`） | SVG 被等比放大到卡片宽度 |
| `public/style.css`（`svg.chart text`） | `font-size:12.5px` | 12.5px 是**用户单位**，随 viewBox 同步缩放 |
| 实际卡片内容宽度 | 1440 视口下约 1100px（侧栏 224 + 两处 20px padding + 卡片 18px×2） | 缩放系数 ≈ 1100/640 ≈ **1.7** |
| 结论 | 刻度 / 图例 / 轴说明的实际渲染 ≈ **21–22px** | 图里文字比正文（12.5–13px）还大，压过曲线 |

同类问题还有：`onechart` 的 `chartPanel` 同样写死 `W = 640`（`var W = 640, H = 300`），
`svg .ax{font-size:12.5px}` 同样被放大。用户看到的"字体太大"是**布局缩放**，改字号只会让 1:1 时又变小。

### 1.2 文案太多：单页渲染文本量实测（A / B 两档案，去掉标签后的可见字符数）

测量方法：Node 载入 `demo-data.js` + `app.js`，对 A/B 两档案逐页 `renderPage`，去标签后计字符数（v0.1.2 实测）：

| 页面 | A | B | 说明 |
| --- | ---: | ---: | --- |
| dash 看板 | 2511 | 2586 | 6 张常驻卡 + 2 个折叠区 |
| mol 分子线 | **6561** | **6196** | 单页 8 张卡（趋势 / 可比性 / 词表 / 表单 / 治疗路径 / TFR 入口 / 手工入口 / 状态演示） |
| trial 临床试验 | 2676 | 2662 | 入组档案 + 三档比对 + 试验列表全平铺 |

长段落实例（v0.1.2 渲染文本）：

- 「默认只显示「阶段名 · 日期 · 一句话概要」；点开看五块细节（方案 / 指标和趋势 / 影像发现 / 副作用总结 / 心理与营养措施和效果）。打印时全部展开。」——**80 字**
- 「口径说明：阶段按门诊记录 / 报告日期切分；「实际」只照抄处方变更线与门诊记录，不做推断。每阶段固定五块，缺内容写「无 + 说明」，不省略块。」——**71 字**
- 「相邻两点「实验室不同」或「IS 标化不为 1」→ 图上断开折线并标注「不可比（实验室/标化不同）」。任一要素缺失时显示「未记录」。」——**65 字**
- 「四要素（单位 / 实验室 / IS 标化 / 灵敏度）在分子线页逐点列出；相邻点不可比时断开折线。」——**49 字**
- 「资料导入（候选 → 核对）与临床试验（M4 数据未接入）从本卡「⋯ 更多」和「准备复诊」路径进入。」——**49 字**

这些句子的共同问题：**解释实现规则，不是给患者下一步动作**。患者读完仍不知道该点哪。

### 1.3 标签页缺失：内容按"卡片堆"而不是按"一次任务"组织

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| `pageMol()` | 只有 3 个 tab：`趋势与词表` / `指标卡（分系列·翻面）` / `复查记录 CML-LAB（二级）` | 「趋势与词表」一页同时放曲线、可比性表、词表、录入表单、治疗路径、TFR 入口；词表没有独立页 |
| `pageMol()` 的 tab 名 | 「趋势与词表」把两类无关信息绑死 | 想看词义必须先看曲线；想录入必须先滚过词表 |
| `index.html` 侧栏 | 10 个一级页平铺（`#navList` 单层 `<ul>`） | 入口是"工具清单"（TFR 档案 / 副作用日志 / 资料导入），不是患者旅程 |
| `pageDash()` | 状态卡 → 今日/接下来 → 档案 / 分子速览 / 副作用速记 / 费用速记 → HVT 信号 → 手工入口 | 首屏要读 6 张卡；主题入口不存在 |

| `pageMed()` | `今日打卡` / `依从日历` / `处方变更`，治疗路径却长在 `mol` 里 | 主题归属错位 |

### 1.4 AI 提醒：只有"把提示词塞进草稿"，没有结果落点

- 页头只有一颗 `和 AI 讨论`（`PAGE_AI` / `data-act="discuss"`）：派发 `cml:agent-draft` + 请宿主拉起原生会话，**不代发**（这是正确的红线）。
- 但页面上**没有任何地方显示"提醒/洞察"**：没有卡片、没有状态（未生成 / 已请求 / 不可用）、没有关闭按钮。
- 失败时只有底部 toast（`page-flash`），刷新即消失；用户无法判断"是没生成，还是我没看到"。

## 2. 主题化信息架构（GranPal 的 4 个主题）

设计约束（来自用户反馈，写成可验收的数字）：

- 每个主题 **恰好 3 步**（上限 5）：`浏览 → 获取 → 采纳 / 记录`。
- 每一步只承载 **1 类信息**；一个页面 / 标签页最多 **2 类信息**。
- 主题名用**患者要办的事**，不用系统模块名。

实现位置：`THEMES`（`public/app.js`）是主题、顺序、入口文案的唯一来源；看板 `themeGrid()` 与侧栏分组都按它组织。

| # | 主题（患者原话口径） | 第 1 步 · 浏览 | 第 2 步 · 获取 | 第 3 步 · 采纳 / 记录 | 每屏信息类型 |
| --- | --- | --- | --- | --- | --- |
| T1 | **指标怎么走**（"这次数值和上次比，变化在哪里？"） | 看趋势 `#mol` · 曲线 + 实验室/标化 | 翻历次 `#mol/cards` · 指标卡（正面最新值 / 背面小图） | 记一笔 `#mol/lab` · 5 字段复查记录 | ① 视图控制 ② 曲线；卡片页 ① 卡片 ② 图例 |
| T2 | **这次复查要问什么**（"把数值变成能开口问的问题"） | 看问题清单 `#prep` · 问题 + 本人口径 | 补报告出处 `#docs` · 文件与字段候选 | 带走资料包 `#prep` · 导出（private 过滤） | ① 清单 ② 导出产物 |
| T3 | **用药与不良反应**（"今天吃了没、哪里不舒服"） | 今日打卡 `#med/checkin` · 已服 / 漏服 | 记一次不舒服 `#ae` · 5 字段自述 | 看处方变更 `#med/rx` · 分段表 + 原因原文 | ① 时间线 ② 录入表单 |
| T4 | **长期安排**（"停药条件、费用和临床研究，慢慢看"） | 停药条件 `#tfr` · 书面条件 + 三态 | 记一笔费用 `#cost` · 5 字段票据 | 研究字段 `#trial` · 三档比对（非资格判断） | ① 对照表 ② 三态按钮 |

补充：

- `#onechart`（多条指标叠看）与 `#fert`（生育计划）作为"还可以直接去"的次级入口，不单独立主题——它们不是每天/每次复查的主路径。
- 红线保持：`tfr` / `fert` 不出现 AI 生成入口；`tfr` 的"三态"只记字段是否出现在报告里。
- 侧栏改成 4 组 + 看板：指标怎么走（指标趋势 / 多条指标）· 这次复查要问什么（复查问题 / 报告资料）· 用药与不良反应（服药与打卡 / 不适记录）· 长期安排（停药条件 / 费用 / 生育 / 临床研究）。

**验收口径**：任一主题从看板进入，完成"看 → 拿 → 落"只需 3 次点击；每次点击后落点页面首屏的可见信息类型 ≤2。

## 4. AI 洞察方案

### 4.1 目标形态与用户的期望

用户期望："指标分析后通过 AI 分析给出提醒信息；后台静默发送提示词并更新结果（集成 LLM 通道）。"

目标形态（若通道存在）：

1. 用户完成一次指标写入 / 打开看板时，**后台静默**提交一段固定提示词（不弹聊天窗）；
2. 结果回到**卡片**（"提醒"卡），不是聊天气泡；
3. 用户可关闭卡片；失败时卡片显示「未生成」，**不显示编造内容**。

### 4.2 本轮真实实现（通道不可用时的降级）

`insightCard()`（看板）+ `localInsights()` + `insightPrompt()` + `state.insight` 状态机：

| 状态 | 触发 | 卡片显示 | 是否伪造内容 |
| --- | --- | --- | --- |
| `idle`（默认） | 打开看板 | 「未生成 · 本机未接入模型（提醒由本机规则算出，不是模型分析）」 | 否 |
| `requested` | 用户点「请 AI 分析（发给对话草稿）」，且页面在 DSH 宿主内 | 「已把提示词放进 AI 对话草稿（未发送）；分析结果留在宿主会话里，不回填本卡片」 | 否 |
| `unavailable` | 用户点击，但页面独立打开（无宿主会话） | 「本机未接入模型：提示词只在页面内生成，没有发往任何服务器」 | 否 |
| `dismissed` | 点「收起提醒」 | 只留一行「已收起 + 展开提醒」 | 否 |

**没有 `generated` 状态**：代码里没有任何分支会把规则文案标成"AI 分析结果"。
本机规则提醒（最多 5 条，全部带来源、无判读）示例：

- 最近一条分子学记录：日期 + 距今天数 + 实验室 + IS 标化；
- 相邻记录中不可比断点数量；
- 下一次门诊复查日期 + 日期差（写明"日期减法，不是系统排期"）；
- 写有「未与医生提过」的不适记录条数；
- 最近一月自费合计（不跨药混算）；
- 待核对的字段候选条数。

### 4.3 提示词模板（已落代码 `insightPrompt()`）

```
【提醒分析请求 · 只整理事实】
档案 <A/B>（<姓名> · 患者本人/家属代记）
本机已记录的事实：
1) <事实>（来源：<来源>）
...

请只做三件事：① 按时间复述这些事实；② 指出其中互相不一致或不可比的条目；
③ 列出仍缺记录、只能写「未记录」的字段。
不要给诊断、判读、治疗或停药建议；不要补写任何缺失值；没有把握就写「未记录」。
```

模板的三个硬约束与既有红线一致：只整理、不判读；缺失写「未记录」；TFR/生育页不生成（`AI_FORBIDDEN`）。

### 4.4 结果落点与关闭

- 落点是看板 `section.insight-card`，**不是聊天记录**；消息只说明状态，不冒充分析结论。
- 用户可「收起提醒」；收起后仍可「展开提醒」（`state.insight.dismissed`）。
- 失败 / 通道缺失一律降级为「未生成」，不写"分析中…"来假装正在跑。

### 4.5 若通道真的可用（未来接入点）

代码只留了一条**不会自动触发**的入口：用户点击 → 生成提示词 → 交给宿主原生会话草稿。
若要变"后台静默"，必须先满足 §5.3 的前置条件；本轮**没有**用定时器、fetch 或本地模型假装。

## 5. 可行性评估：宿主是否真的提供后台 LLM 通道？

结论：**不提供**。证据如下（均为本仓源码 / 官方快照，不是推断）。

### 5.1 证据链

| # | 证据 | 位置 | 说明 |
| --- | --- | --- | --- |
| E1 | 服务端插件注入只有 `webServer` + `connection` | `dsh/index.js:22` `export const inject = ['webServer', 'connection']` | 没有 model / llm / agent 服务 |
| E2 | 服务端能力自述只有三项 | `dsh/routes.js` 的 `/health`：`capabilities: ['health','ui','demo-readonly']` | 没有 generate / completion 路由 |
| E3 | 整个包没有出站 HTTP / 模型凭据调用 | `grep -rn "fetch(\|https://\|api_key\|Token" dsh lib public/bridge.js` 只命中 `http://localhost`（URL 解析）与 GitHub repository 字面量 | 不存在"悄悄调用模型"的代码 |
| E4 | 渲染侧唯一的 AI 面是宿主传入的 `conversation` 节点 | `lib/client.js`（`conversation` prop；"AI 对话还没开始"占位） | 插件只能排版/显隐宿主会话，不能向它"后台提问并取回文本" |
| E5 | 宿主未暴露写草稿能力时的既定做法是"如实提示" | `lib/client.js` 的 `cml:agent-draft` 分支："宿主没有暴露写入草稿的能力时，如实提示「请手动复制」，不假装已填" | 与"静默发送"直接冲突 |
| E6 | 官方布局合同只要求"把 conversation 节点放到合适位置" | `reference/official/development-2026-10-09.md:178/183/235` | 全文没有后台 LLM / 文本生成 API |
| E7 | 脚手架边界自述 | `docs/02-DSH-CONTRACT.md` 末尾："脚手架不会替宿主实现不存在的能力" | 明确不能靠猜 API 补齐 |

### 5.2 判定表

| 能力 | 是否可用 | 依据 |
| --- | --- | --- |
| 后台静默调用宿主 LLM 并取回结构化结果 | **否** | E1/E2/E4/E6：没有服务、没有 API、没有结果回传通道 |
| 插件自带 API Key 直连外部模型 | **否（且不应做）** | E3：本仓无凭据实现；`docs/18-MINERU-PARSING.md` 的凭据纪律要求用户显式触发并告知外发；"静默"会绕过知情同意 |
| 把提示词放进宿主原生会话草稿（用户可见、可改、自己发） | **是** | E5 + `bridge.js` → `lib/client.js`，v0.1.2 已实测有反馈 |
| 本机确定性规则提醒（日期差、断点、计数） | **是** | 纯函数，无外部依赖；本轮已实现 |

### 5.3 变成"可行"需要什么（交接条件，不是承诺）

1. 宿主公开一个**服务端或渲染侧**的模型服务（例如 `inject: ['model']` 或 postMessage 协议），并给出稳定签名、配额与失败语义；
2. 明确**知情同意与外发范围**：哪些字段会出本机、发送给谁、保留多久；默认关闭，用户显式开启；
3. 给出**结果回填通道**与版本号（哪次评估对应哪版档案），否则无法回答"这条提醒是否过期"；
4. 医疗红线的技术保证：TFR/生育页不进入模型上下文；模型输出不得落成"判读列"。

在上述条件满足前，任何"静默 AI 分析"都只能是演示；本仓选择**不做假数据、不假装已接入**。

## 6. 能否作为整仓迭代范式？

### 6.1 判断

**可以作为"方法范式"，不能作为"页面模板"直接复制。**

可复用的四件事：

1. **主题化 IA**：主题 = 患者要办的事；每主题 3 步 `浏览 → 获取 → 采纳/记录`；主题是 `THEMES` 单一来源，看板与侧栏同源。
2. **信息预算**：每屏 ≤2 类信息；单页文案量有基线（本轮把 mol 默认页 6561 → 1015 字，dash 2511 → 1480 字，trial 2676 → 849 字）并可被脚本复算。
3. **标签页拆分规则**：一个标签页只回答一个问题；拆分时"不删事实、只搬家"，并在文档里留去向表（§3.2）。
4. **AI 能力闸门**：先证明通道，再写功能；不可用时只做"规则提醒 + 用户主动触发"，状态如实（未生成 / 未接入），永不伪造。

不能直接复用的三件事：

1. **主题内容**：T1–T4 来自 CML 的复查 / 用药 / TFR 旅程；换癌种必须重做（沿用"主题=患者任务"的方法，不沿用标题）。
2. **红线位置**：TFR / 生育的"不 AI 生成"是 CML 特有决策红线；其它病种要重新识别自己的红线页。
3. **宿主能力结论**：§5 的"不可行"只对当前 `development-2026-10-09` 快照与本仓有效；宿主升级后必须**重新取证**，不能把本文当永久结论。

### 6.2 范式落地清单（给下一个仓）

- [ ] 先写 `PILOT-VNEXT-DESIGN.md` 同等物：现状实测（字号 / 字数 / 标签页）、主题表、拆分去向表、AI 可行性证据。
- [ ] 把主题定义做成**唯一数据源**，看板入口与侧栏分组都从它渲染。
- [ ] 每个标签页标注"承载哪 2 类信息"，超过 2 类就再拆。
