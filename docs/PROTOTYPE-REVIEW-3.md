### ⑦ IP6 新口径 —— **口径部分合理（不是纯掩盖），但掩盖了一个真问题：两个「更正」是空壳**

先给"这个口径能不能用"的独立判断，再说数字。

**(a) 口径本身是否合理。** 声明口径 = 「只算在本页原地打开表单的入口；跳转到别的页面的快捷入口不算；行内三态切换、表单内提交按钮、顶栏设置弹窗、面板拖拽、`fert-ask` 都不算」。我**接受其中大部分**：

- 排除"跳转型快捷入口"**合理**。看板上的「记一笔复查」「记一次不舒服」「记一笔」实测点击后 `location.hash` 从 `#dash` 变为 `#mol` / `#ae` / `#cost` —— 它们不在本页编辑，把它们算进"本页显式编辑入口"确实会重复计数。
- 排除"表单内提交按钮"**合理**：提交与打开表单是同一件事的两半。
- 排除"行内三态切换"**合理**：`tfr-state` 是单选三态，不是表单。
- 排除 `fert-ask`（只滚动+高亮清单，`app.js:1957-1960`）**合理**：它确实不产生编辑。
- 排除"面板拖拽/顶栏弹窗"**合理**（非内容编辑）。

**(b) 按该口径实测的违反页数 = 0。** 逐页真点、比对点击前后 `location.hash`：

| 页 | 候选数 | 原地打开 | 跳转 | 结论 |
| --- | --- | --- | --- | --- |
| `dash` | 3 | **0** | 3（`mol-new`/`ae-new`/`cost-new` 全部 nav） | 按口径 **不计** |
| `mol/lab` | 1 | 1（`记一笔复查（血常规 / 骨髓）`） | 0 | 1 ✓ |
| `ae` | 1 | 1（`记一次不舒服`） | 0 | 1 ✓ |
| `cost` | 1 | 1（`记一笔`） | 0 | 1 ✓ |
| `fert` | 1 | 1（`加入清单`） | 0 | 1 ✓ |
| `docs` | 1 | 1（`选择文件`） | 0 | 1 ✓ |
| 其余 7 页 | 0 | 0 | 0 | 0 ✓ |

A/B 两侧完全一致。**声明口径下 IP6 违反 = 0 页。**

**(c) 但这个口径漏掉了一个比"两个入口"更严重的问题。** 按"任何写操作入口"的严格口径仍超限 2 页：`mol` = `保存（写入本机内存态）` + `改这一条（更正，不删除）`（`app.js:1170`）；`docs` = 三行各 `接受` + `更正` = 6（`app.js:1664-1665`）。我进一步实测这两个**「更正」到底做了什么**：

| 按钮 | 点击前 | 点击后 | 是否产生可观察结果 |
| --- | --- | --- | --- |
| `mol-correct`（`app.js:1929`） | `pcr=4`，`#aiHint` 空，inputs 6 | `pcr=4`，`#aiHint`=「更正模式：打开同一条记录的历史版本链（本机内存态）。」，inputs 6 | **否**。只改一行提示文案，不弹表单、不写记录、不改数据 |
| `docs-correct`（`app.js:2008-2011`） | `accepted={"A":{},"B":{}}`，`#docsAcceptedLine`=「已接受：A-C3（共 1 条，本机内存态）」 | `accepted={"A":{"A-C1":"已更正"}}`，`#docsAcceptedLine` **一字未变** | **半否**。写了 `state` 但行内汇总不刷新、无更正内容入口、`lastWrite=null` |

推论：这两个"编辑入口"**不提供任何编辑能力**。所以：
- 从"入口会不会太多"的角度看，严格口径把它们算作编辑入口是**高估**，声明口径的放宽**有事实依据，不是纯掩盖**；
- 但从"患者能不能真的操作并看到结果"的角度看，它们是**更严重的缺陷**：界面上写着「更正（不删除）」，患者点了，什么都没发生（`mol`），或者只是内部状态翻了一下而屏幕文字不变（`docs`）。**一个点了没反应的"更正"按钮，比多一个入口糟得多。** 口径放宽恰好让这个问题从 IP6 统计里消失了。

→ IP6 判定：**口径可接受，但不得用来关闭"更正不可用"这条缺陷**（见 §4 P1-1）。
